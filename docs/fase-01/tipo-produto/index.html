O commit, e não o nome variável da branch nem a versão isolada de um pacote npm, constitui a linha de base reprodutível do código-fonte. A documentação abaixo descreve o conteúdo inspecionado nesse commit; não representa medição de qualidade concluída nem auditoria da infraestrutura de produção.

2. Classificação segundo Pressman​

O Excalidraw enquadra-se principalmente como aplicação Web (WebApp): é oferecido ao usuário final por interface gráfica em navegador, suporta criação e edição de desenhos e pode prestar serviços colaborativos. Pela finalidade, também é software de aplicação voltado à produção de diagramas, esboços e conteúdo visual. Essas categorias descrevem dimensões diferentes e não precisam ser tratadas como mutuamente exclusivas.

A presença do pacote @excalidraw/excalidraw acrescenta a perspectiva de componente de software reutilizável, incorporável a outras aplicações React. Não se afirma que o projeto seja software embarcado, de tempo real, de sistema operacional ou que todas as funcionalidades da aplicação estejam presentes na biblioteca. A aplicação hospedada inclui capacidades de persistência e colaboração que não se confundem com as funcionalidades básicas do componente npm.

3. Classificação segundo a IEEE 1062: COTS, MOTS e FD​

A classificação depende do objeto e da modalidade de aquisição/uso. Os termos são aplicados aqui como categorias de análise, sem sugerir que uma licença open source determine, por si só, uma classificação de aquisição:

ModalidadeAplicação ao casoJustificativa
COTS (Commercial Off-The-Shelf)Aproximação funcional para adoção da aplicação e consumo do pacote distribuído sem alteração do código-fonteO produto está disponível, reutilizável e pode ser empregado como fornecido. O termo commercial tem conotação de aquisição: por ser software aberto, não cabe declarar enquadramento contratual formal sem examinar o contexto de aquisição.
MOTS (Modified Off-The-Shelf)Possibilidade condicionada a modificações do código-fonte do Excalidraw para atender necessidades própriasIntegrar a API pública ou configurar a biblioteca não implica, por si só, modificar o produto. Há MOTS quando a organização altera o software adquirido/adotado.
FD (Fully Developed)Não descreve a adoção do produto preexistente pela equipeSó seria aplicável a uma solução integralmente desenvolvida para o demandante, ou a um novo produto construído desde o início.

Conclusão contextual: para esta avaliação, o Excalidraw é um produto de prateleira preexistente, open source, com aplicação e biblioteca. Considera-se o uso as-is próximo ao cenário COTS; alterações no código poderiam configurar MOTS. A ambiguidade entre aplicação completa e componente reutilizável está explicitada, sem atribuir a ambos os mesmos requisitos de integração e operação.

Pergunta da aulaResposta fundamentadaEvidência e ressalva
Que funções executa?Criação/edição de cenas em canvas; inserção de formas, texto, desenho livre, setas e imagens; desfazer/refazer; biblioteca de elementos; importação/exportação; na aplicação web, colaboração e salvamento local.README distingue recursos do editor e recursos adicionais de excalidraw.com.
Quais janelas ou interfaces?Editor visual no navegador, barras e menus, diálogos de importação/exportação e integração por componente React.packages/excalidraw/components/. Não se estabelece contagem fixa de janelas, que depende da versão e do estado da interface.
Quem usa?Pessoas criando desenhos, estudantes, docentes, profissionais de produto, equipes colaborativas, desenvolvedores integradores e mantenedores/contribuidores.Perspectivas detalhadas em Partes interessadas.
Qual conhecimento é exigido?Uso básico de interface gráfica para o editor; conhecimento de React/JavaScript e gestão de dependências para integrar a biblioteca; conhecimento de Node/Yarn/TypeScript para desenvolver o monorepo.packages/excalidraw/README.md.
Qual massa de dados é manipulada?Cenas com elementos, estado da aplicação e recursos binários (p.ex., imagens). Requisitos de software?Para usuário final, navegador compatível; para integração, React/React DOM e dependências do pacote; para desenvolvimento do repositório, Node.js ≥ 18 e Yarn 1.22.22 declarados no manifesto raiz.package.json do monorepo, excalidraw-app/package.json e manifesto da biblioteca.

O projeto é um monorepo com workspaces (excalidraw-app, packages/*, examples/*). Os pacotes citados são identificáveis no commit de referência, mas isso não significa que todos sejam publicados separadamente ou tenham API estável.

packages/excalidraw/Editor React reutilizável, componentes de UI, cena, ações, renderização e APIs de importação/exportação.index.tsx, components/, data/, scene/, renderer/ e package.json.

5.1 Diagrama de contexto e arquitetura​

Figura 1 — Visão lógica simplificada dos componentes no commit de referência. As setas representam dependências ou interações conceituais, não o mapa completo de importações de código.

A biblioteca permite incorporar o editor em outra aplicação React, que deve prover contexto de execução e interface conforme a API do pacote. A colaboração e determinados fluxos de persistência pertencem à aplicação e usam serviços externos; não devem ser atribuídos automaticamente à distribuição npm.

5.2 Interfaces e dependências​

  • Interface humana: canvas, ferramentas, menus, diálogos e controles para mouse, toque e teclado conforme o ambiente.
  • Interface de integração: o pacote npm expõe o componente React Excalidraw, tipos e utilitários; a integração exige o CSS do pacote e um contêiner com altura definida (guia oficial).
  • Persistência local: LocalData.ts usa armazenamento do navegador; políticas de quota, privacidade e comportamento offline dependem do navegador e do contexto de execução.
  • Comunicação colaborativa: Collab.tsx coordena a colaboração; firebase.ts implementa interações de armazenamento remoto. Serviços externos não estão integralmente cobertos pelo código do cliente inspecionado.
  • Empacotamento e ambiente: o monorepo utiliza Yarn Workspaces; o pacote npm informa dependências React por peerDependencies; a aplicação usa Vite, e a distribuição web usa as APIs suportadas pelo navegador.

6. Restrições e implicações para a avaliação​

AspectoO que é possível avaliar com as evidências disponíveisLimite e tratamento
ManutenibilidadeModularidade, organização de workspaces, dependências declaradas, regras de lint/tipagem, arquivos de testes e histórico Git.Isso não prova, isoladamente, baixo esforço real para manutenção nem cobertura funcional efetiva.
ConfiabilidadeImplementações de recuperação, persistência, gerenciamento de erros, PWA e estratégias de colaboração descritas no código.Inspeção estática não comprova disponibilidade de produção, ausência de perda de dados ou tolerância real a falhas. Testes controlados exigem protocolo e ambiente próprios.
FlexibilidadeCompatibilidade declarada, API pública, instruções de instalação, workspaces e mecanismos de importação/exportação.Declarações de suporte não equivalem a testes em todos os browsers, hardwares e cargas. Escalabilidade requer cenários e medições reproduzíveis.
